# AE32000 (EISC) ISA notes

Working reference for the compiler. The MDIN-6xx's internal MCU ("IMCU") is an ADChips
AE32000-family core. MIT's own datasheet
(`MDIN-6xx data 2026Aug07/01_Document/Datasheet/EmbeddedMCU/`) covers only the chip around the
core (memory map, cache, serial flash, peripherals), not the instruction set.

The full "AE32000C Instruction Set Architecture Reference Manual" (`AE32000-isa-rm_ko.pdf`) is
cited by both documents but does not appear to be published.

The documents describe AE32000**C** (Lucida). Which revision and options the MDIN core has is
not documented: the DSP-extension instructions (shaded in Table 2.3: `MRS`, `MIN`, `MAX`, `ABS`,
`SADD*`, `AVG*`, `UPK*`, `MACS/MACB/MSOP*`) are **unverified on the MDIN** and must be tested on
hardware before the compiler emits them. The assembler accepts them, which proves nothing about
the silicon.

## Programmer's model

- 16 GPRs `%R0..%R15`, 32-bit.
- SPRs: `SR, PC, LR, ER, MH, ML, MRE, CR0, CR1`. `%SP` is addressed by its own instruction forms
  (`LD/ST (%SP,off)`, `LEA (%SP,off),%SP`, `PUSH/POP`); whether it aliases a GPR is not stated.
- `ER` (extension register) is loaded by `LERI` and consumed by the next instruction that takes
  an immediate/offset. Hardware folds LERI; pushing `ER` pushes 0.
- `MH:ML` hold the 64-bit product of `MUL`/`MULU` (`%Rd` also gets `ML`), and the `MAC`
  accumulator. Read with `MFMH`/`MFML`.
- Flags in SR: C, Z, S (sign), V. Conditional jumps as in the quick reference.
- All instructions are 16 bits. Little-endian halfwords.
- I-SPM fetch is 1 cycle but a data read from I-SPM is 3 (MIT datasheet): tables belong in D-SPM
  or in LERI/LDI immediates, not inside a stage blob.

## LERI and immediates (verified against gas)

`LERI imm14` = `01iiiiiiiiiiiiii`. The first LERI of a chain sign-extends its 14 bits; each
further LERI does `ER = ER << 14 | imm14`. The consuming instruction then combines `ER` with its
own field. Rules observed from `gas` (the assembler that built code which runs on the device):

| Form | Without LERI | With LERI | One LERI while ER fits |
|---|---|---|---|
| `LD/ST (%Ri,off)` | 4-bit field × 4 (0..60) | `ER<<4 \| field<<2` (gas uses field 0..3) | 13 bits |
| `LDS/LDSU/STS (%Ri,off)` | 3-bit field × 2 (0..14) | `ER<<4 \| field<<1` | 13 bits |
| `LDB/LDBU/STB (%Ri,off)` | 3-bit field × 1 (0..7) | `ER<<3 \| field` | 13 bits |
| `LD/ST (%SP,off)` | 7-bit unsigned × 4 (0..508) | `ER<<4 \| field<<2` (as `LD`) | 13 bits |
| `LDB/LDS/LDBU/LDSU/STB/STS (%SP,off)` (E8–EA) | as the `%Ri` forms | as the `%Ri` forms | 13 bits |
| `LEA (%SP,off),%SP` | 8-bit signed × 4 (−512..508) | `ER<<4 \| field<<2` | 14 bits |
| `LEA (%Ri,imm),%Rd` (E4), `LSEA (%Ri,imm),%SP` (E1C), `LESA (%SP,imm),%Rd` (E1D) | offset 0 | `ER` (no field) | 14 bits |
| `LDI imm,%Rd` | 8-bit signed (−128..127) | `ER<<4 \| field[3:0]` | 14 bits |
| ALU `op src/imm,%Rd` (`ADD ADC SUB SBC AND OR XOR CMP MIN MAX AVG* SADD* MAC* MSOP*`) | low nibble is **a register** | `ER<<4 \| field[3:0]` immediate | 14 bits |
| `TST MAC MUL MULU` immediates | low nibble is a register | `ER<<4 \| field[3:0]` | 13 bits |
| `ROL/ROR imm,%Rd` | 3-bit count (0..7) | `ER<<3 \| field` | 14 bits |
| `ADDQ/CMPQ imm5,%Rd` | 5-bit signed (−16..15) | not extended | |
| `ASR/LSR/ASL/SSL`, `MRS` | 5-bit count or a register; MRS 3 bits | not extended | |
| `Jcc/JMP/JAL off8` | `PC+2 + 2·sext(off8)` | `PC+2 + 2·(ER<<8 \| off8)`, PC = the branch itself | 14 bits |

"One LERI while ER fits": gas uses a single LERI for ER in that signed width, two LERIs
(`sext(L1)<<14 | L2`, 28 bits) beyond it. The 13-bit limit is gas's choice, not the hardware's
(LERI sign-extends 14 bits); the encoder copies it so it only emits encodings gas has emitted.
Byte offsets past 28 bits take three LERIs as a plain chain (`sext(L1)<<28 | L2<<14 | L3`).
`LEA/LSEA/LESA` past 28 bits take three LERIs composed as `L1<<18 | L2<<4 | L3[3:0]` — a different
rule from the byte forms. Neither three-LERI form has been checked on hardware; the encoder refuses
them and the compiler builds large constants with `LDI` (two LERIs at most).

The linker relaxes label branches to the shortest form (gas alone emits two LERIs and a
relocation for every label).

Consequences:
- An ALU op with an immediate always costs a LERI, even for 0 (`add 0,%R4` = `leri 0; add 0x0,%R4`).
- `gas` silently corrupts some operands, and the encoder refuses them instead: misaligned offsets
  lose their low bits (`ld (%R1,3)` assembles as offset 0, `lea (%SP,x)` likewise), odd `MUL`
  destinations are rounded (below), and a shift count of 32 spills into the register-form bit
  (`asr 32,%R6` assembles as `asr %R0,%R6`).

## Register-field traps (verified against gas)

- `MUL/MULU src,%Rd`: the destination field is 3 bits and means an **even** register
  (`R0,R2,…,R14`). `mul %R6,%R5` assembles as `mul %R6,%R4` with no warning. gcc only uses
  even destinations.
- `MIN/MAX/AVGB/AVGS`: destination `R0..R7` only (Table 2.3 note).
- `UPK*`: source is an even register pair.

## Oracle

`tool/gen_oracle.dart` disassembles all 65 536 words alone, after one LERI and after two
(`test/golden/objdump_p{0,1,2}.txt.gz`). Caveats found while building it:
- `objdump` steps one byte over the reserved `0xB780..0xB7FF` encodings (`unknown`), misaligning
  everything after; each word therefore gets its own label (objdump resyncs at symbols).
- `objdump` collapses zero words to `...` unless given `-z`.
- `objdump` mis-decodes (each checked against gas; `test/isa_objdump_test.dart` lists them):
  `LDI`'s field printed unsigned (it is signed); `LD/ST (%SP,off)` ignoring a preceding LERI; and
  the bare opcode word of several groups (every operand field 0) mis-extended after a LERI
  (`leri 0x1555; add %R0,%R0` → `0x56dd5550`, where the rule gives `0x15550`).
  Treat `objdump` as a cross-check and `gas` as the authority for encodings.

## Tests

- `test/isa_gas_test.dart`: every gas golden line (≈3 100 forms) encodes to the same words,
  decodes back to the same instruction, and gas's rejections and silent corruptions are refused.
- `test/isa_objdump_test.dart`: the decoder agrees with objdump on all 65 536 words alone, after
  one LERI and after two, except the coprocessor/debug/unpack groups the compiler never emits and
  the objdump bugs above.
